inspection

The hero surface. Every run shows a captured-frame stage — exactly what Argus saw when it acted — alongside a step-by-step timeline, model reasoning, and an assertion diff when things go wrong.

  • Test tree with real-time pass / fail / flaky indicators

  • Per-step model reasoning — why the model chose this action
  • Assertion diff: expected vs actual, side-by-side
  • YAML editor with live resolved-step preview
  • Provider config: Anthropic, OpenAI, Ollama, Gemini, Azure, LiteLLM

Web dashboard · argus serve

Monitor at
a glance

The self-hosted web dashboard gives teams a shared view of test health — KPIs, trend charts, and flakiness scores that auto-refresh every 30 seconds.

  • Pass rate, run count, avg duration, flaky test count
  • 14-day stacked pass / fail trend (pure CSS, no chart library)
  • Per-test flakiness score with last-12-runs sparkline
  • Cross-adapter run history table with provider column
  • Environment selector — staging, production, local

CLI · argus run · CI/CD

Tests that
stream live

The CLI is the primary interface for developers and CI/CD pipelines. Each step prints as it completes — pass, fail, or skip — with agentic reasoning annotations and a structured diff on assertion failure.

  • argus run / watch / init / record / report / serve
  • Per-step ✓ / ✗ / ⊘ with durations as they happen
  • Agentic action notes — what the model actually did (↳)
  • Expected vs actual diff on assertion failure
  • exit 0 on all pass, exit 1 on failure, exit 2 on crash
  • ARGUS_PROVIDER · ARGUS_API_KEY · ARGUS_TARGET env vars
