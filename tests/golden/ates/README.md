# Golden ATES evidence stores (C-03)

These files pin what the current Python implementation **writes** as ATES evidence for a real
`argus run`, and what its verifiers **decide** about that evidence, so the Rust implementation
can prove specification C-03: "evidence written by the Python implementation MUST verify under
the Rust implementation", and the same tampering MUST be rejected.

Everything here is generated by `scripts/golden/export_ates.py`. Do not edit the generated
files by hand. Edit the exporter and regenerate them instead.

```sh
python scripts/golden/export_ates.py --write   # regenerate (Linux only)
python scripts/golden/export_ates.py --check   # exit 1 and name each drifting file
```

## Layout

| Path | Written by | Contract |
|---|---|---|
| `stores/<case>/project/.argus/<case>.test.yaml` | the exporter: the CLI spec that was run | input |
| `stores/<case>/project/.argus/runs/RUN-<id>/evidence.jsonl` | `AtesEventStore` during `argus run` (canonical events, one per line) | C-03 canonical evidence |
| `stores/<case>/project/.argus/runs/RUN-<id>/run.json` | finalization binding (`ates-finalization-binding-v1`) | C-03 |
| `stores/<case>/project/.argus/runs/RUN-<id>/manifests/` | `manifest-0001.json` (evidence) and `package-manifest-0001.json` | C-03 |
| `stores/<case>/project/.argus/runs/RUN-<id>/audit.jsonl`, `approvals.jsonl` | audit ledger (`ates-audit-ledger-v1`) and approvals | C-03 |
| `stores/<case>/project/.argus/runs/RUN-<id>/reports/` | derived reports (`report.json`, `report.md`, `report.html`, `junit.xml`) and `report-manifest-0001.json` | C-03 derived reports |
| `stores/<case>/project/.argus/runs/.ates-runtime-identity.key` | the project's runtime identity key, which keys the `hmac-sha256` commitments in `RUN_STARTED` | C-03 |
| `expected/<case>.json` | `argus run` exit code, effective status, event types in order, exported files, and `inspect_finalization_trust`, `verify_finalized_run` and `verify_report_bundle` on the untouched store | C-03 verify (Python → Rust) |
| `expected/tamper.json` | the same three verifiers on copies of `stores/cli-pass` with one member changed, truncated or removed | C-03 rejection |
| `_manifest.json` | file list and hashes, Python source hashes, and in `generated_with` the git commit, package version and Python version (`--check` ignores `generated_with`) | all |

Cases:

| Case | What runs | Effective status |
|---|---|---|
| `cli-pass` | `python3 -c "print('OK')"`, two passing assertions | `passed` |
| `cli-fail` | a command that writes `boom` to stderr and exits 3; one assertion fails | `failed` |
| `cli-launch-error` | a program that does not exist | `failed` |

Lock files (`*.lock`) are not part of a store: the writer and the verifiers create them on
demand. Legacy run history files (`<stamp>-<spec>.json`) are C-02 and live in
`tests/golden/state`.

### Runtime identity key: TEST ONLY

`.ates-runtime-identity.key` is **TEST ONLY** key material. The exporter replaces
`os.urandom` with a SHA-256 counter over a fixed label, so the key, and every HMAC commitment
made with it, is the same on every run. It protects nothing.

## Determinism and environment

The run happens in a child process with a scrubbed environment: `HOME` and the XDG
directories point into a fresh temporary directory, `TZ=UTC`, no `ARGUS_*` or provider
variables are inherited, sockets are refused and no model is called (every step is a
deterministic assertion). The worker imports every `argus` module and then:

- replaces `datetime.datetime` in every `argus.*` module with a subclass whose `now()` starts
  at 2026-01-01T00:00:00Z and advances 1 ms per call;
- makes `time.time`, `time.time_ns`, `time.monotonic` and `time.perf_counter` advance in the
  same 1 ms steps;
- replaces `uuid.uuid4`, `secrets.token_bytes`, `secrets.token_hex` and `os.urandom` with
  SHA-256 counters over fixed labels;
- pins `argus.__version__`, which `RUN_STARTED` records, to `0.0.0+golden`.

The CLI targets run `python3` from `PATH`, so neither the spec nor its HMAC source commitment
contains a host path. The exporter refuses to commit a store that verifies differently from the
live run, and fails if any tampered copy is accepted by all three verifiers.
