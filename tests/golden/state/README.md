# Golden state fixtures (C-02, C-06)

These files pin how the current Python implementation **writes** and **reads back**
persisted user state, so the Rust implementation can prove that existing installs
"load and display identically" (specification C-02) and that the secret store keeps
its location, format and references (C-06). They cover the parity-inventory rows
*Run history*, *Token usage persistence*, *Desktop conversation store* and
*Knowledge files* (parity-inventory §2).

Everything here is generated by `scripts/golden/export_state.py`. Do not edit the
generated files by hand. Edit the exporter and regenerate them instead.

```sh
python scripts/golden/export_state.py --write   # regenerate (Linux only)
python scripts/golden/export_state.py --check   # exit 1 and name each drifting file
```

Every expected file has `"schema": "argus-golden-state-v1"`, a `case` id, the
`api` it records and the recorded `value`. The Python commit and version that
produced the fixtures are in `_manifest.json` → `generated_with`. The
`implementation.sources` hashes make a change to any writer or reader show up as drift.

### Secret store: dummy values only

The store holds only `golden-dummy-not-a-secret` variants. `secrets.key` is
**TEST ONLY** key material: its 32 bytes are the ASCII text
`TEST ONLY golden key; not secret`. The exporter installs it in place of a random key.
SQLite page bytes depend on the library version, so `--check` compares
`secrets.sqlite3` through its logical dump (schema and rows) and not byte for byte.

## Determinism and environment

The writers run in a child process. `HOME` and `XDG_{CACHE,CONFIG,DATA,STATE}_HOME`
point into a fresh temporary directory, `TZ=UTC`, `COLUMNS=120`, no `ARGUS_*` or
provider variables are inherited, sockets are refused and no provider is
constructed. Nothing is written outside that temporary directory and this folder.
Documented monkeypatches in the worker make two runs byte-identical:

* `time.time` / `time.time_ns` → a frozen clock that the exporter moves explicitly,
  starting at 2026-01-01T00:00:00Z. `RunResult.started_at` is passed explicitly
  because its dataclass default captured `time.time` at import.
* `uuid.uuid4` → SHA-256 of a counter. This covers run storage ids and knowledge
  `bug_id`s.
* `secrets.token_bytes` → the TEST ONLY key for 32-byte requests, and counter-derived
  bytes for AES-GCM nonces.
* `argus.secrets.datetime` → a frozen `datetime.now`. Real stores carry
  microseconds, for example `2026-01-01T03:01:00.123456Z`. The frozen clock has none.
* `ArgusAPI._conversation_identity` is pinned to fake paths: `/golden/project`,
  `/golden/legacy-project` and `/golden/non-list-project`. A real window pins
  `project_identity(project)` when it opens. The fake identity keeps the committed
  per-user key (`sha256(identity)[:24]`) independent of the temporary directory.
  `identity.json` records the derivation inputs.

Absolute temporary paths in recorded output are replaced by `<PROJECT>`,
`<STATE_HOME>`, `<DATA_HOME>`, `<CONFIG_HOME>`, `<HOME>`, `<TMP>` and `<REPO>`.

## Using the fixtures from another implementation

1. Copy a section's tree into a temporary directory. Never read or write it in place.
2. Point `XDG_STATE_HOME` or `XDG_DATA_HOME` at the copied `xdg-state` or `xdg-data`
   directory.
3. Git does not keep file modes. Before opening the copied secret store, restore
   `0700` on `argus/secrets/` and `0600` on both files. Python refuses the store
   otherwise; see `permission_enforcement`.
4. For conversations, use the fake identities above instead of the copy's real path.
   Alternatively, derive the key from your own path with the recorded rule.
5. Compare your loader's output with `expected/*.json` after the same path-token
   normalization.

## Adding a case

1. Add the scenario to the matching section function in
   `scripts/golden/export_state.py` (`_history`, `_tokens`, `_conversations`,
   `_knowledge`, `_secrets`). Use the real writer. If you hand-make a file, list it
   under "Hand-made inputs" with the reason.
2. Use only dummy values, fake paths (`/golden/...`) and ASCII file names. Keep each
   repository-relative path under 160 characters (the longest today is 158) so
   Windows checkouts stay within `MAX_PATH`.
3. Run `--write` twice and confirm that nothing changes on the second run. Then run
   `--check`. Review the diff and update this README when you find a new behaviour.

## Notable current behaviours

These are facts about the Python implementation as recorded, not endorsements.
The Rust port must reproduce them, or record a deliberate deviation in the
specification.

**Run history**
* Rows sort by the 20-digit allocation order in the name, not by the timestamp.
  After a wall-clock rollback, the `rollback.test.yaml` run has an older stamp
  (`20251231-230000`) but sorts newest. The `.storage-order` counter holds the
  highest order handed out.
* Legacy names (no order field) always sort after every allocation-ordered name,
  by their first 15 characters, descending.
* Rows that fail to parse or fail `valid_run_history` are skipped and do not count
  toward `limit`. `recent_runs(3)` still returns three real runs.
* There is no `cancelled` status. Valid statuses are `pass`, `fail`, `error`,
  `running` and `skipped`, and a `"cancelled"` row is ignored. A run the user
  stopped is stored as `fail` with a skipped step noted `skipped: stopped by you`.
  `recent_runs` and `argus report` show `fail`. Only the desktop card
  (`_run_card_status`) shows `stopped`.
* `running` is a valid history status. Re-saving a result rewrites the same flat file
  and `result.json`.
* Two runs of the same test in the same second get distinct names through the order
  field. Unsafe filename characters become `_`. Names over 120 UTF-8 bytes are cut
  and suffixed with a 12-hex SHA-256 digest (`bounded_name`).
* `recent_runs` reports `id` as `history:<flat file name>`, `steps` as
  `"<passed>/<total>"` and `duration` rounded to 0.1 s. The defaults are 20 for
  `recent_runs`, 50 for `load_runs` and 10 for `argus report`.

**Token usage**
* `.argus/usage.json` is a running total that every process merges into. Desktop
  `session` usage exists only in memory. Trackers with zero calls are not charged.
* A corrupt `usage.json` reads as zeros, and the next `persist` silently replaces it,
  so the earlier totals are lost.
* A file without `total_tokens` loads as is, and `argus tokens` then crashes with
  `KeyError`. A JSON list loads as a list, and `argus tokens` crashes with
  `TypeError`. Unknown keys are preserved by `persist`.

**Conversations**
* The store is `<gui_state_root>/projects/<sha256(identity)[:24]>/conversations.json`.
  `gui_state_root` is `$ARGUS_GUI_STATE_DIR`, then `$XDG_STATE_HOME/argus`, then
  `~/.local/state/argus`. A relative `XDG_STATE_HOME` is accepted, unlike the secret
  store.
* `save_conversations` keeps the first 30 chats plus any chat whose `busy` is
  exactly `true`. `"true"` and `1` are dropped. `load_conversations` returns
  whatever is stored and does not trim. The file is compact JSON with `\uXXXX`
  escapes for non-ASCII characters.
* The legacy `.argus/gui/conversations.json` is migrated once: truncated to 30,
  written to the per-user store, then deleted.
* A store that is not a JSON list, or a window opened without a project, loads `[]`.
* `project_identity` is `normcase(resolve(path))`. On Linux, `normcase` does nothing.
  On Windows it lowercases and uses backslashes, which is not exercised here.

**Knowledge files** (JSON store)
* `<key>.graph.json` is single-line compact JSON:
  `{"nodes": {id: {window_title, desc, visit_count, bug_found, first_seen,
  last_seen}}, "edges": [[from, to, label, success], ...]}`. The NDJSON files are
  append-only, one object per line.
* `get_stats()` with no target keys results by `Path.stem`, for example
  `notepad-exe.graph`. `get_stats(target)` keys them by the raw target string.
* A failing assertion is stored as a bug titled `assertion:<type>` with
  `actual: "assertion_failed"`. A passing assertion is not stored.
* `confidence_for_state` returns 0 on a freshly opened store until a call loads that
  target's graph.
* `target_key` lowercases, collapses non-`[a-z0-9]` runs into `-`, trims and cuts at
  40 characters, and falls back to `target`.
* **Limit:** only the JSON-store dialect is produced. The `local`, `docker` and
  `external` backends write `<key>.graph.json` as networkx `node_link_data`, which
  needs networkx and is not installed or required here. chromadb vector indexes are
  out of scope (C-02: rebuilt, never loaded).

**Secrets**
* References must match `^secret://argus/[A-Za-z0-9][A-Za-z0-9._/-]{0,127}$` with no
  `..` segment, and the match is case-sensitive. **`SECRET://ARGUS/NAME`, the spelling
  used in specification C-06 and the CLI help, is rejected.** `a//b` and `a/./b` are
  accepted.
* `argus secrets set --stdin` stores the value with its trailing newline.
* `argus secrets list` prints sorted references, one per line, never values.
* The location is `$XDG_DATA_HOME/argus/secrets`. An empty `XDG_DATA_HOME` falls
  back to `~/.local/share` and a relative one is an error. Windows uses
  `%APPDATA%\Argus\Secrets` and macOS uses `~/Library/Application Support/Argus/Secrets`,
  neither of which is exercised here.
* Format: table `secrets(ref TEXT PRIMARY KEY, protected BLOB NOT NULL, updated_at
  TEXT NOT NULL)`. On POSIX, `protected = b"A" + nonce(12) + AES-GCM(ciphertext+tag)`
  with the reference as associated data and a raw 32-byte `secrets.key`. Windows
  stores `b"D" + DPAPI blob` and is not exercised here.
* The directory must be mode `0700` and the files `0600`. A group- or world-readable
  `secrets.sqlite3` blocks `list` and `get`. A readable `secrets.key` blocks only `get`.
