# Golden Fleet wire messages (C-04)

These files pin the Fleet messages the current Python implementation exchanges between a Node
and the Control Center, so the Rust implementation can prove specification C-04: "all
`argus-fleet-*-v1` identifiers and message formats stay identical, so a fleet can mix Python
and Rust nodes during migration."

Everything here is generated by `scripts/golden/export_fleet.py`. Do not edit the generated
files by hand. Edit the exporter and regenerate them instead.

```sh
python scripts/golden/export_fleet.py --write   # regenerate (Linux only)
python scripts/golden/export_fleet.py --check   # exit 1 and name each drifting file
```

## Layout

| Path | Written by | Contract |
|---|---|---|
| `expected/messages.json` | for every signed kind (`node-enrollment`, `node-enrollment-ack`, `node-heartbeat`, `node-clock-probe`, `fleet-placement-authorization`, `fleet-generation-retirement`): the message fields, the exact canonical bytes that are signed (`canonical_signed_message`, `argus-fleet-node-ed25519-v1`), the Ed25519 signature, the verifier's decision, and its decision after one field is changed | C-04 message format and signatures |
| `expected/flow.json` | one flow through the real registries: bootstrap credential, pending and active enrollment, a replayed acknowledgement, the heartbeat payload, digest and receipt, the clock probe challenge and assessment, the session request payload and digest, the placement record, the authorization payload, Node admission, and ATES transport (binding, batch canonical lines, receipts, a replayed batch, a foreign-Node rebind, and whether the Control Center mirror matches the Node's lines) | C-04 behaviour |
| `expected/identifiers.json` | every module-level `argus-*-v1` version identifier in `argus/fleet` | C-04 identifiers |
| `keys/node.key.json` | `NodeKeyPair.save`: the `argus-fleet-node-key-v1` private key file | C-04 key file format |
| `keys/public.json` | the Node and Control Center public keys and fingerprints | inputs |
| `_manifest.json` | file list and hashes, Python source hashes, and in `generated_with` the git commit, package version and Python version (`--check` ignores `generated_with`) | all |

### Keys: TEST ONLY

Both keys are **TEST ONLY**. They are Ed25519 keys whose 32-byte seeds are SHA-256 of fixed
labels in the exporter, so they protect nothing. Ed25519 signatures are deterministic, so every
signature here is reproducible. The bootstrap credential's secret is not recorded.

## Determinism and environment

The flow runs in a child process with the same scrubbed environment and deterministic patches
as `tests/golden/ates` (`scripts/golden/_harness.py`): frozen clocks, counter-based `uuid4`,
`secrets` and `os.urandom`, sockets refused. Every timestamp the flow passes to the registries
is a fixed value. The exporter fails if a valid message is rejected, if any tampered message is
accepted, or if the Control Center's ATES mirror differs from the Node's canonical lines.
